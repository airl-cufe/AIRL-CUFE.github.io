AIRL USER GUIDE

From first login
to first job.

Step-by-step guidance for requesting an account, connecting to the cluster, preparing your environment, and getting help.

Home/ Documentation
01 — REQUEST AN ACCOUNT

Start with a
supervised project.

Access is granted after the application is reviewed by lab administration and your faculty supervisor or PI confirms the project.

01APPLICATION

Choose a request type

Submit a research application or a graduation project application using the lab form. The form may require Google sign-in.

Open access form ↗
02PROJECT DETAILS

Prepare your information

Researchers: full name, faculty email, department, supervisor, experiment and dataset details, and estimated size. Project teams also provide member names, project impact, and data contribution.

03SUPERVISOR CONFIRMATION

Ask your supervisor to email AIRL

Your faculty supervisor or PI must send a short confirmation to AIRL2026@hotmail.com, verifying your work.

04ACCOUNT SETUP

Watch for setup instructions

Account creation is manual and may take about 2–3 weeks. Approved users receive their SSH username, temporary password, storage quota, and training material by email.

!
Keep credentials private.

Never share passwords, SSH keys, or accounts. Contact AIRL through the team email if you suspect your credentials have been compromised.

02 — CONNECT TO AIRL

Choose the right
way in.

Use the credentials and access method provided for your account. Cluster resources are shared; run computational workloads through Slurm.

WEB PORTAL · JUPYTER

Use JupyterHub

Open the AIRL JupyterHub portal and sign in with the GitHub account associated with your faculty email.

Portal login screen ↗Authentication screen ↗Unapproved account screen ↗
SSH · TERMINAL

Connect from your computer

Open a terminal and replace [username] with your AIRL account username:

ssh [username]@airlws02.tailf6a96c.ts.net

On first connection, verify the host fingerprint. Enter the temporary password supplied by the lab when prompted, then follow the instructions to set up SSH-key access.

For macOS/Linux, or Git Bash/WSL on Windows, you can install your public key with:

ssh-copy-id [username]@airlws02.tailf6a96c.ts.net

Keep the private key on your own device and protect it with a passphrase.

Shared cluster reminder

The login node is for login, editing files, downloading data, and submitting jobs. Run compute workloads on allocated compute resources through Slurm—not directly on compute nodes without administrator authorization.

03 — REMOTE DEVELOPMENT

Use VS Code
thoughtfully.

Remote SSH can make development convenient. To reduce load on login nodes, use a compute node for work beyond simple editing.

01

Adjust Remote SSH settings

Set Connect Timeout to 60 seconds. Set Max Reconnection Attempts to 0 (or at most 1) to avoid repeated authentication attempts and possible account lockout. Enable Show Login Terminal when troubleshooting.

02

Configure SSH hosts

Add a login host and a compute host in your SSH config. Replace USERNAME with your own username and use the node name assigned to your interactive job.

Host airl-login
  HostName airlws02.tailf6a96c.ts.net
  User USERNAME

Host airl-compute
  User USERNAME
  HostName nodename
  ProxyJump airl-login
03

Start an interactive job first

Log in to the cluster, start an interactive Slurm job with resources appropriate to your work, then note the allocated compute-node hostname.

04

Connect to the allocated node

Update the compute host's HostName to the allocated node and connect to that host in VS Code. Avoid running a full VS Code session on a login node.

CLUSTER MAINTENANCE

Plan around scheduled restarts.

  • Monthly maintenance: first Monday, about one day
  • Login node restarts: Monday at 9:00 AM, about 15 minutes
  • If Monday is a holiday, the restart moves to Tuesday
Schedules may change; ask AIRL for current service notices.
04 — FILES & FIRST JOBS

Start small.
Back up what matters.

Keep files in the right place and validate your workflow with a small test before scaling up.

FILESYSTEMS

Choose a storage area

  • Home: code, software, notebooks, and important personal project files. Quota is 10 GB.
  • Project: datasets and trained models for an approved project; allocations vary by project.
  • Scratch: temporary data and intermediate outputs for active jobs. Not backed up; old files may be automatically removed.

The documentation also describes a shared Pool area as a staging location; Pool is not backed up. Confirm the available paths and quotas with AIRL.

Large datasets over 100 GB need lab-administrator approval before upload. Avoid duplicate copies of public datasets where possible.

FIRST TEST RUN

Validate before scaling

  1. Choose a small example that checks your code and data pipeline.
  2. Use your provided starter scripts in /workspace where available.
  3. Submit a test batch job with sbatch /workspace/train.sh.
  4. Check the job result, logs, resource use, and output before scaling up.

Ask AIRL if you need help choosing the correct Slurm options. Do not guess resource parameters for a production job.

!
Do not use AIRL systems for sensitive data.

The systems are designated for low-security data only. Do not store personal or financial data, unanonymized data, data under NDAs, national-security-restricted data, or data requiring security controls or audit tracking.

05 — GET HELP

Ask the whole
AIRL team.

Email AIRL2026@hotmail.com. The team mailing list helps route your question to the right person. Please don't email individual staff directly for support.

HPC Help and Office Hours are also held several times each week for drop-in questions and troubleshooting.

INCLUDE THESE DETAILS WHEN RELEVANT

  • The command or job script you ran
  • Your Slurm job ID(s)
  • What you already tried
  • The complete error message
  • Relevant code, scripts, or screenshots
